# Data dictionary — "Analyse des clients" synthetic dataset

Generated by `generate_dataset.py` (seed = 42, fully reproducible). 5 tables, designed as a
small star schema around shared keys. All foreign keys are guaranteed to match (asserted in code).

## Tables & grain

| Table | File | Grain (one row per…) | Rows | Role |
|---|---|---|---|---|
| Customer Analysis | `customer_analysis.csv` | customer | 2000 | Fact |
| Targets | `targets.csv` | Vehicle Class | 6 | Lookup / dimension |
| Offers | `offers.csv` | State × Offer × Vehicle Class | 120 | Aggregate |
| Renewals | `renewals.csv` | State × Renew Offer Type × Month | 240 | Aggregate |
| Policy Holders | `policy_holders.csv` | State × Month | 60 | Aggregate |

## Shared keys (the columns that must agree across tables)

- **State** — 5 values: Arizona, California, Nevada, Oregon, Washington
- **Vehicle Class** — 6 values: Two-Door Car, Four-Door Car, SUV, Sports Car, Luxury Car, Luxury SUV
- **Month** — 12 values, always paired with **Month Order** (1–12) so it sorts/joins correctly
- **Renew Offer Type / Offer** — 4 values: Offer1–Offer4

## Intended relationships (cardinality, all one-to-many → fact)

| From (dimension, "one") | To (fact/aggregate, "many") | On |
|---|---|---|
| Targets | Customer Analysis | Vehicle Class |
| (State dim) | Customer Analysis, Offers, Renewals, Policy Holders | State |
| (Month dim) | Renewals, Policy Holders, Customer Analysis (via Expiry Month) | Month |

## Key assumptions made

1. **Customer Analysis is the only true fact** (customer grain). The other three "aggregate"
   tables are independent monthly/categorical summaries, exactly as in the original IBM sample.
2. **Targets is a Vehicle-Class lookup.** The module exposes `State`, `Month`, `Month Order`,
   `Year` columns too, but the report only ever consumes Targets *by Vehicle Class*, so those
   columns are set to a whole-year, all-region snapshot (`State = "All Regions"`, `Month =
   "Full Year"`, `Month Order = 0`). Flagged because it's an assumption, not a fact.
3. **Targets.Value reconciles to the fact table.** `Value` = the actual average CLTV per class
   computed from the 2000 customers; `Target` is set 8% above it. So the lookup and the fact
   tell the *same* story — the bug the earlier audit found (CLTV summed vs averaged) is avoided
   here by deciding one convention up front.
4. **CLTV is correlated, not random:** driven by Income, Vehicle-Class weight (luxury worth
   more) and tenure, and reduced by open complaints. So segment comparisons are meaningful.
5. **`Premiums Over Claim`** is a *derived* column: `Monthly Premium × Months Since Inception −
   Total Claim Amount`. Included to show a computed measure living in the source.
6. **Month is text + a numeric companion** (`Month Order`, and `Month Key` = YYYYMM in the fact).
   This mirrors the real model's `Month Order` / `Month Key` and is the clean way to handle the
   "text months don't sort" trap.
